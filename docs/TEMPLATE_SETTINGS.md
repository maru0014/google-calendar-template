# 通知・予定色のテンプレート設定

## 対応範囲

- 予定色は小さい予定画面と**詳細画面**（「その他のオプション」で開く画面）で適用します。折り畳まれた設定欄は自動で展開します。小さい予定画面の説明も必要に応じて展開して入力します。
- 通知は時刻付き予定に対応します。方式は「通知」「メール」、最大5件、0〜40320分前です。
- 終日予定の通知設定、小さい予定画面での通知適用は未対応です。指定された場合は案内を表示し、成功扱いにしません。説明・色など他の対応項目は適用される場合があります。
- 予定色は、確認済みの24色と「カレンダーの既定色」に対応します。該当色がない画面では別の色へ代替しません。
- カレンダー自体の色、ラベルの作成・編集、独自通知エンジンは対象外です。
- データは従来どおりローカル保存です。予定の最終保存は利用者が行います。

## 設定の意味

| 項目 | 選択 | 動作 |
| --- | --- | --- |
| 通知 | 未指定 | 予定の通知を変更しない |
| 通知 | 通知なし | 既存の通知を削除する |
| 通知 | 既存を置換 | 指定した通知一覧にする。既存行を再利用し、不要な行だけ削除する |
| 通知 | 既存に追加 | 既存の通知を保持し、同じ方式・同じ分数の通知を重複追加しない |
| 予定色 | 未指定 | 予定色を変更しない |
| 予定色 | カレンダーの既定色 | 予定固有の色指定を解除する |
| 予定色 | 指定色 | 色見本・色名・色コードを確認して選ぶ |

テンプレートを編集して「未指定」に戻すと、保存した設定も解除されます。既に開いている予定の通知を消す操作とは異なります。

追加後に通知が5件を超える場合は通知を変更しません。既存の通知に重複がある場合、追加モードではその既存行自体を削除しません。

## 互換性と失敗時の扱い

- 旧テンプレート・旧JSONに新項目がなければ未指定です。既存の保存キー、配列形式、日時形式は維持します。
- 新バージョン間では通知・色をJSONで往復できます。不正な新設定を含むインポートは全体を中止し、既存データとバックアップ履歴を変更しません。
- **旧拡張へ新JSONをインポートすると、新しい通知・色項目は旧拡張の処理で失われます。** ダウングレード前には新しいJSONを別に保管してください。
- UI要素の欠落、曖昧な色候補、反映を確認できない場合は失敗を表示します。通知の変更途中で失敗した場合は、予定を保存する前に通知を確認してください。自動で元に戻る保証はありません。
- GoogleカレンダーのUI更新や言語によってコントロールを認識できない場合があります。実UI確認済みは日本語画面です。

## ローカル確認手順（push前）

1. 現在の拡張でテンプレートをJSONエクスポートし、比較用に保管します。
2. `npm run build` 後の `dist` をChromeの開発者モードで読み込み、再読み込みします。別の作業ツリーの `dist` を読み込んでいる場合は、今回のフォルダへ切り替えてください。
3. Googleカレンダーのタブも再読み込みし、**新規の未保存予定**を詳細画面で開きます。
4. 旧テンプレートを適用し、通知・色が変わらないことを確認します。
5. 通知あり（置換）に「通知10分前・メール60分前」、予定色に指定色を設定して適用し、行の方式・時刻・色の選択を確認します。
6. 追加モードで同じテンプレートを2回適用し、通知が増えないことを確認します。上限超過時は失敗表示と既存通知の保持を確認します。
7. 通知なしと既定色を試し、未指定と異なることを確認します。管理画面で設定を未指定へ戻して再編集し、解除が保持されることを確認します。
8. JSONエクスポート→インポートで新設定を確認します。インポートは従来どおり追記であり、同じIDは再採番されます。
9. 小さい予定画面で説明・色の欄を閉じた状態から適用し、説明と色が反映されることを確認します。説明は添付ダイアログを開かずに展開されることも確認します。小さい予定画面の通知、終日通知、対象色がない画面では誤った成功表示をしないことを確認します。
10. 確認用予定は保存せず閉じます。実際の保存後の通知動作確認は利用者判断で行ってください。

高速に切り替えた場合は進行中の適用が完了した後、最後に選んだテンプレートを適用します。途中の選択は省略します。色パレットが閉じ、最後の内容になったことと、小さい予定画面内で上下のホイールスクロールができることを確認してください。

v0.5.3の実機テストではスクロールは完全には解消していません。v0.5.4はレビューで指摘された反映待ち・後処理・エラー理由の保持を改善した版です。実機での完全解消は未確認です。

自動テストは `npx vitest run`、型チェックは `npx tsc --noEmit` です。
